## Reproduced colour-preservation failure

Preview's ten comment-only edits retain byte-identical decoded Highlight
appearance programs, QuadPoints and original colours. Monight's subsequent
comment-only saves change six of those marks' colours: Yellow `#FFCD45` becomes
`#FFCD44`, Blue `#6CB4F5` becomes `#6BB4F5`, Purple `#B78CF2` becomes `#B78BF2`,
on both page rotations. Their appearance streams change too. Green and Pink
retain exact colours in this run. Geometry remains within 0.001pt.

Native-origin marks reproduce the discrepancy: Preview yellow
`[0.980392, 0.803922, 0.352941]` becomes
`[0.97647059, 0.80392158, 0.34901962]`; the Acrobat heading Highlight's green
channel changes from `0.384308` to `0.38039216`. Native readers still display
the correct placement and named colours, but a comment edit must not change
colour or regenerate a native appearance. This record does not waive that failure.
The exact conversion root cause remains unproven; issue #127 identifies
where the existing appearance-preservation adapter excludes Highlight.

## Creation gate

Remove Highlight from the single verified-tools list. That removes it from the
split-button menu, Tools > Annotate and the engine's allowed creation tools.
The split button uses the next admitted tool, Underline. Existing Highlight
display, preservation during other edits and print paths remain supported; its
editing interaction is locked. The native save adapter is unchanged.
The retained executable predates this suspension and is the exact candidate
used for the native matrix. Final production changes suspend Highlight interaction/creation and ensure
runtime calls honour the engine tool locks. No geometry or save behaviour is
claimed fixed by this verification change.

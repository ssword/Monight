Problem

Three adapters repeat viewer mutation, state save, and UI refresh; their wide context interfaces expose the implementation choreography.

Solution

Deepen one reader actions module; keep DOM, keybind, and Tauri modules as thin adapters at a single seam.

Benefits

  • locality: one action path
  • leverage: three adapters
  • Tests hit one interface
  • Delete repeated choreography
Deletion test: deleting the repeated adapter logic concentrates the same semantics in one module; no reader capability disappears.

Problem

Solution

Problem

Solution

Problem

PDFViewer mixes document loading, queries, rendering, gestures, annotations, and printing; tests bypass its interface by constructing uninitialized instances and assigning private implementation state.

Solution

Deepen a cohesive internal document-feature module around PDF.js semantics and caching; keep page-surface rendering mechanics local to the rendering implementation.

Benefits

  • locality: PDF.js semantics concentrate
  • leverage: every document tool
  • Interface becomes test surface
  • Private casts disappear
Deletion test: PDFViewer passes strongly; this is an internal seam inside an already deep module, not a split based on file size.

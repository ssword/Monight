### The finding that matters: navy does not survive on dark

Both failed images failed the *same* way for the *same* reason. On a near-black
field the navy mark has essentially zero contrast, so the model compensates —
once by giving it embossed highlights, once by inverting the wordmark to cream.
This is not the model being lazy; it is a genuine brand problem.

**Fix to carry into the VI: define a knockout/reversed variant** (mark in paper
white or moonlight cream, crescent kept cream or converted to a knockout) and put
it in the logo spec beside the 单色版. Without it there is no usable artwork for
dark backgrounds — and this is a night-reading brand, so dark backgrounds are the
main case, not the edge case.

That makes three variants the spec needs: 主版 (navy + cream crescent),
单色版 (one-colour, crescent knockout), 反白版 (for dark fields).

## New direction from ssword: Monet / 莫奈

ssword's idea: "Monight" also reads as "Monet", so fold Monet's impressionist
style into the brand. Response given — worth preserving the reasoning:

**The sharp edge of it.** Impressionism's core is *soft edges, visible brushwork,
form dissolving into light*. The mark just locked is *hard-edged geometry that must
survive monochrome and 16px*. Those two cannot coexist on the same element —
brushwork on the M would destroy its scalability and its mono reduction.

**Also: "Monet" is a protected brand name.** The reading pun can live in internal
copy, but the word Monet must never appear in the identifier. Flagged to ssword.

**Where Monet genuinely belongs** (four layers, mark untouched):

1. **Colour** — impressionist colour logic is specific and usable: shadows are not
   black but blue-violet, highlights run warm, transitions carry blue-green. Extends
   the existing palette by adding *mid-tone richness only*, keeping exactly one warm
   highlight so the cream-against-navy impact ssword liked stays intact.
2. **Atmosphere** — brushwork texture, water-lily, water-glint and mist motifs for
   launch screen, site hero, empty states, release art. Soft edges are fine there.
3. **Product (highest value)** — Monight already ships a filter configurator. A
   built-in preset named 印象 / Impression that renders pages in Monet's warm soft
   register puts the brand *inside the feature*. Echoes 「一页月光」: same light,
   different hour.
4. **Series logic** — Monet's *series* (haystacks, Rouen, water lilies — one subject
   re-painted through changing light) becomes the brand's editorial grammar: one mark,
   one page, shown across lights and themes. Directly defines the social templates
   and launch screen series.

**The real link is light, not the pun**: *Impression, Sunrise* is one light in a haze
— the same construction as 「一页月光」. Monight's product core is the state of light
on a page.

**Recommendation given**: layer it, don't style the mark. Offered an optional
brushwork-mark test only if ssword wants to see the tradeoff.

**ssword's answers**: 分层落地 (colour + atmosphere + product preset), and
**放开色板** — the full impressionist bright set goes in, accepting that cream is
no longer the only focal point. So I set one guardrail: **氛围色不进入标志**.

### Lesson worth reusing

**Never let image generation carry authoritative text.** Hex values, spec labels
and type specimens must be supplied as text, not baked into a rendered sheet. Same
failure class as the CJK glyph problem — the deliverable is an image, the *spec*
is data. Deliver specs in chat or a token file.

### 莫奈滤镜界面示意

One 1024×1536 portrait sheet: the same reading interface re-lit three times —
night / dusk / morning. This is the product-layer landing of the Monet direction.

**The good news**: telling the model to draw every line of copy as an abstract bar
worked perfectly. This is the first sheet in the whole project with zero garbled
text — the technique is the fix for the problem found two batches ago. Reuse it.

**The remaining flaw**: the symbol in each toolbar is not the locked mark — the M is
narrower, the crescent is not the concentric-arc construction, and it was recoloured
per panel (gold-on-navy, gold, white) so it matches none of the three defined

not. Reported, not auto-fixed.

### Reusable conclusions from this whole project

1. Generated images can never carry authoritative text — hex values, spec labels,
   CJK wordmarks. Deliver those as text.
2. Ask for abstract bars instead of placeholder copy when a layout needs to look
   populated. It removes the gibberish-text failure entirely.
3. A logo locked as flat geometry still gets restyled by the model on dark fields;
   always ship a 反白版 so the model has a legal option.
4. State the do-not-change list per derivation, and read every output back before
   claiming it passed.

### Decisions worth remembering

- **Three-step navy ramp**, not two. The shell must stay dark for night reading
  (夜蓝·暗), and only genuinely floating layers get 夜蓝. Two steps would make the
  toolbar as bright as a dialog.

### Tooling gotcha (cost me a lot of time this session)

**Never put multiple `Edit` calls for the SAME file in one assistant message.** They
race on the file snapshot and most get silently dropped — *even though every call
reports "Successfully edited file"*. Reproduced repeatedly; sometimes 1 of 3 landed,
sometimes 2 of 4, sometimes the last, sometimes a middle one. Cross-file batching in
one message is fine. Reliable pattern: one edit per file per message, or rewrite the
whole file with `Write`, then **always confirm with a grep for the new values** —
never trust the success message alone.

## 2026-09-13 (later still) — 预览页已真机验证

Correcting my own earlier note: I claimed the preview page couldn't be rendered here.
**That was wrong.** ssword pushed back on it and was right — verifying is worth the
setup, and in the end *nothing needed downloading*.

### How

Playwright's browsers were already cached at `~/Library/Caches/ms-playwright/`,
including `chromium_headless_shell-1234/chrome-headless-shell-mac-arm64/chrome-headless-shell`
— the purpose-built headless binary that exits cleanly (the full Chrome app with
`--headless=new` just hangs). Drove it over CDP for **element-level crops at 2x**
instead of one tall downscaled page shot: `Runtime.evaluate` +
`getBoundingClientRect` for the rects, then `Page.captureScreenshot` with
`clip` + `captureBeyondViewport`. Zero npm packages — Node 22's global `fetch` +
`WebSocket` are enough. Script kept at `/tmp/monight-verify/cdp-shot.mjs`.

Two traps worth remembering: the environment sets `HTTPS_PROXY`, so `curl` to
`127.0.0.1` silently went through the proxy and reported success before the DevTools
port was actually up (probe with `curl --noproxy '*'` and check the body); and the
Node CDP client needs the proxy vars unset or it throws `ECONNREFUSED`. Also
`pip install Pillow` fails — outbound network is blocked — so do crops via CDP, not
by installing an image library.

### What the render confirmed

- **Reader shell** — toolbar is 夜蓝·暗, not cream. The "cream band" I'd worried about
  in the thumbnail was just the `.preset-btn.active` pill (暖米底 + 墨夜蓝字). Inactive
  presets read fine as paper-white text on a faint outline.
- **Settings page** — sidebar active item = 夜蓝 fill + inset cream bar; cards on
  夜蓝·暗; toggle-on = cream track + navy knob, toggle-off = dark navy track + paper
  knob; key badges and the dashed `+ Add` in cream; delete `×` in the warm red;
  **`Reset` renders paper-white on 夜蓝 — the `.btn-secondary` 1.7:1 bug is visually
  confirmed fixed.**
- **Swatches** — the navy ramp reads as a clean progression (墨夜蓝 → 夜蓝·暗 → 夜蓝),
  and the derived 分隔线 `#2C4460` sits just above 夜蓝 as intended.

Verdict: the palette alignment renders correctly on both surfaces. Nothing further to
fix here.
